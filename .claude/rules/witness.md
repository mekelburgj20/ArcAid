# Arcaid Witness, VPX ingest, integrity, attempts — rules

Loads when you touch the Witness device ingest/verification, VPX score routing, Sanctioned-play integrity, Limited attempts or invite-only tournament entry. Cross-cutting invariants live in the root CLAUDE.md; this file is the detail for this domain.

## Arcaid Witness — devices and the verify-join (v2.142.0 + v2.145.0, ADR 0020)
- **The device reports over a synchronous GET.** An app on the cabinet reports table `launch_ts`/`exit_ts` (epoch SECONDS, device clock) into `witness_observations` over a **GET** — the AtGames SDK offers no POST — authenticated by a device-scoped token bound to the device id (`witness_devices.atgames_unique_id` — an `ATGAMES_UNIQUE_ID` for a cabinet, a per-install UUID for the Castcade companion).
- **`witness_devices.device_type` is `atgames` | `desktop` (migration 183, v2.163.0).** `GET /api/witness/pair?type=desktop` sets it; an unknown value is a 400 `DEVICE_TYPE_INVALID` refused BEFORE the single-use code is consumed; the cabinet sends no type.
- **The column is read in exactly ONE place, `authenticateDevice`,** which hands it to `VpxScoreIngestService.provenanceFor` — cabinet → device `atgames` / legacy platform `vpxs`, desktop → `pc` / `vpx`. That is the ONE mapping for the room write, both Global writes and the tournament device-exclusion check; nothing else in the SCORE path gates on it, and the lobby grades both kinds by the same rules. (Log pull and the update offer are cabinet-only and test it too: `logsSupported` in `src/utils/witnessVersion.ts`, `offeredRelease` in `WitnessReleaseService`.)
- **The Castcade companion is the Windows desktop Witness producer** — repo `C:/code/repos/castcade` / github mekelburgj20/castcade, its ADR 0003; its ArcAid asks are in that repo's `docs/arcaid-side-changes.md`.
- **Tokens are minted via a single-use pairing code and stored only as a SHA-256** (`witness_devices.token_hash`); a wrong token gets a bare 401.
- **Pairing a device id the account has never held is capped (W97, v2.243.0):** 10 unrevoked devices per account, 5 new ids per 24 h (`MAX_ACTIVE_DEVICES_PER_USER` / `MAX_NEW_DEVICES_PER_DAY`), 400 `DEVICE_LIMIT` before the code is consumed. A re-pair of the account's own device (live or unpaired) is never counted and existing rows are never touched. The match relay's per-device wrong-code budget (ADR 0039) rests on this.
- **The join is exit ≈ submit.** `WitnessVerifyService.verdictsForRound` joins each `source='atgames'` board row to an observation on **`exit_ts ≈ created_at` (±`JOIN_TOLERANCE_SEC` = 120)** — exit-to-submit makes those the same instant on two clocks, so the join doubles as a device-clock check (drift ⇒ no match ⇒ `unwitnessed`, never a false pass). `launch_ts >= roundStart − LAUNCH_GRACE_SEC` (15) ⇒ `verified`, earlier ⇒ `flagged` (the gear-up P8 exists to catch).
- **Badge, never a gate.** No verdict filters a board or changes a rank, and `unwitnessed` is NEUTRAL (most players have no paired cabinet). The one exception is Witness flag mode in events (last section).
- **`unwitnessed` renders NOTHING (A42, v2.239.0, ADR 0038; owner 2026-11-09).** `WitnessBadge` draws only ✓ (verified) and ⚠ (flagged); the grey "unwitnessed" word read as a cheating mark on AtGames-pulled scores. Never bring back a mark for the absence of evidence.
- **`table_name` is the engine-internal id** — surfaced but **never matched** against the catalogue (different namespaces, no mapping).
- **`created_at` on atgames rows holds ATGAMES' timestamp,** threaded through `ScoreHistoryService.log`'s optional `createdAt` (SQLite UTC shape). Any new ingest path that stamps somebody else's timestamp must pass it, or its scores can never be witness-verified. `isDuplicate` still ignores the column so re-pulls dedup against pre-v2.145.0 rows.

## Three verification tiers (v2.148.0, ADR 0021)
- **Tier 1 = the session join above** (`method:'session'`).
- **Tier 2 = a round-start CHECK-IN** (`GET /api/witness/checkin`, same device-token auth and same bare 401 as `/witness/report`). These cabinets run one thing at a time, so the Witness being open at `server_ts` proves no table was mid-session then: a score that exited after a check-in inside `[roundStart − LAUNCH_GRACE_SEC, score.created_at]` is `verified` with `method:'checkin'` and NO duration.
- **A cabinet's clock can be hours wrong at power-on.** TomatoGrass's 4KP came up ~40 h behind after a power cycle (2026-11-03) and `ntpd -g` stepped it later; every device-stamped field (`launch_ts`/`exit_ts`, a score's `created_at`, the `cab:<launch>` attempt key that `WitnessService.recordAttempt` tests against the game window) can carry that skew. Never build a server rule on "device time is close to now"; the cabinet app (1.0.9) decides power-cut on boot id, not time (W86 is the server-side item).
- **`witness_checkins.server_ts` is the SERVER's clock, always** — a device-supplied time would make tier 2 a self-report worth nothing. Tier 2 only ever UPGRADES an `unwitnessed`, can never produce `flagged`, and never revisits a tier-1 verdict.
- **Tier 3 = retro-derived observations** (`witness_observations.via = 'retro'`, `?via=retro` on the report route, first-writer-wins in the upsert): **same trust, tagged** — never gate on `via`.
- **A check-in proves the CABINET was idle and cannot bind a score to a device** (AtGames exposes only a model code, `AtGamesRanking.hardware`) — accepted, documented, still a badge and never a gate.
- **LU cabinet evidence (v2.205.0, W72):** a launcher record passed as `record=` on `/witness/score` is verified against the Ed25519 keys in `signing_keys` (`SigningKeyService`, `src/utils/luRecordSignature.ts`) → the "Launcher-signed" badge; a record for another game of the sitting withholds the badge, never drops the score. **Table identity on cabinets is NOT the file SHA-256** (LU's DRM makes every shipped file unique): the design is the plaintext-MD5 = manifest `tableChecksum` match in `docs/Arcaid Witness - LU - Record Proposal v1.md` §3 (W78/W87/W88); do not add a cabinet file-hash rule before that lands.
- **Late evidence is re-frozen by `POST /:roomId/admin/tournaments/:tournamentId/reverify`** → `EventResultService.recomputeFrozenResult`, which reuses `computeStandings` + `freeze` and touches NOTHING else: `event_finished_at` and `is_active` are preserved and **nothing is announced** (a second podium post reads as a second event). Throwdowns have no admin surface, so no reverify.

## VPXS auto score collection (P9, ADR 0022)
- **Source: the launcher's own journal, not AtGames.** VPX on an ALP cabinet runs under the third-party **vpx-standalone** launcher, so AtGames never sees these tables and there is NO leaderboard to sync. The Witness reads the launcher's `scoreserver/vpx-<table>-games.jsonl` off the same stick it runs from and reports each completed game to `GET /api/witness/score` (device-token auth, same bare 401 as report/checkin), landing via `VpxScoreIngestService`.
- **Journal shape:** one `game_end` record per SITTING, with every game's balls inside `scores[0].balls` and the top-level score being the LAST game only (FINDINGS-0u, 2026-09-06). The cabinet app splits games at ball-1 restarts and sends a `restarts=N` tally.
- **`score_history.source = 'vpx'` is the fifth value** (migration 172), built on the SHARED `rebuildScoreHistorySource` helper that migration 167 also calls — never hand-copy that create-copy-drop-rename again.
- **The ingest files the GAME as a `witness_observations` row** (`launch_ts` = game start, `exit_ts` = game end): a sitting holds several games, so verifying against the SESSION's launch would flag every legitimate second and third game. Filing the game means the ADR 0020 join needs no VPX rule, only source eligibility in `WitnessVerifyService`.
- **Game rows are keyed apart from the beacon's SESSION row by `witness_observations.kind`** (`'session'` | `'game'`, migration 177, v2.155.4) — game 1 starts the same second the session does and collided on (device, table, launch). The join reads `kind` ONLY as a tie-break: on an equal exit the GAME row beats the SESSION row (v2.158.0).
- **No-ROM exit samples.** `reason=exit_sample` (one score reading at exit, `launch_ts` = the SESSION launch) is stored as `witness_observations.sample='exit'` (migration 179) and can be `verified` (session opened inside the round) or `unwitnessed`, NEVER `flagged` — its launch is a lower bound, not a measurement. An early-session exit sample falls through to the check-in tier like any unresolved row. Verdicts carry `sample` for the badge tooltip. Castcade also sends `exit_sample` for an UNPATCHED table (no sidecar → basic mode: one reading when the player closes or VPX exits), so an exit sample from a ROM table means the importer refused that file, not that the table has no ROM — read `%APPDATA%\Castcade\logs\companion.log` for "not patched (unsupported: …)" (W94, 2026-11-05).
- **A `no_match`/`invalid` answer WARNs with table/rom/slug** — the cabinet never retries a 200, so that line is the score's only trace.
- **Matching mirrors AtGames:** the game's END time decides the round; an early start is `flagged`, never refused at ingest (badge, never gate). Scoped to the player's rooms' ACTIVE rotation games + rounds of events they are in; **pinned boards are deliberately NOT candidates** (no window = unbounded writes from ordinary play at home).
- **Names match on any of journal-name/`rom`/slug** through `normalizeGameName` plus a squashed form (`vpx-badcats` → `badcats`), because `rom` is heterogeneous and sometimes wrong.
- **Global-path name tier (`recordGlobal`, v2.158.0):** between the maker/year hint and giving up, the single candidate whose `normalizeGameName` equals the launcher DISPLAY name's wins — the NORMAL form only, never the squashed slug form (which made "Scooby-Doo!" and "Scooby Doo" indistinguishable); rom/slug are fallbacks, not peers.
- **Filters:** Player 1 only (the launcher stamps the cabinet's own account on every row); games < 20s dropped; the launcher's continuation artifact (a short record starting the instant the last ended, repeating its total) dropped.
- **An unmatched score answers `200 {status:'no_match'}` — NOT a 401** — so the cabinet never retry-loops on ordinary play.
- **Cabinet 1.0.6 last-game score (W48, v2.180.0).** On a `shutdown` record the cabinet sends the record's own top-level score for the LAST game when its last ball scored > 0 (a new game always leaves a trailing 0 entry; some tables, e.g. America's Most Haunted, never get a `game_over` record and never write their last ball); earlier games of a sitting stay `partial=1` floors.
- **`balls=`** (the launcher's per-ball points, raw) is stored as `witness_evidence.ball_points` (migration 195, `parseBallPoints` — malformed is dropped, never a 400) for a future per-ball format; `score − sum(balls)` is what scored after the last recorded ball. No board, rank or rule reads it.
- **Every witness score leaves a trail row (W29, v2.181.0).** Per-board paths write their own; `VpxScoreIngestService.trailBackstop` (run by `ingest` after `ingestNow`) writes one for any outcome that returned before reaching one (invalid, no usable name, deleted, ambiguous with no Global fallback, and any return added later). Every row without a verdict stores the server's reason in `reasons`.
- **Every landed witness score also writes `submissions` (W93, v2.220.0).** The rotation close crowns its winner from `submissions` ALONE (`TournamentEngine` "Top scorer (local DB)"), never from `score_history`; `VpxScoreIngestService.upsertSubmission` runs inside the shared `writeBoardRow` (ingest + host reinstate), keyed `<game id>-<board name lower>` like the web route, higher-only. A new board landing that skips `writeBoardRow` must call it too, or the score can lead the board and lose the close (Krobs / Blegger, RTX 2026-11-04). Migration 206 backfilled the rows written before it.
- **Device TARGET changes are audited** (`audit_log`, action `witness_target_change`, details `{from, to}` with labels) inside `WitnessService.setDeviceTarget`; saving the same choice writes nothing.
- **A play that counts nowhere says why (W27.1, v2.182.0, ADR 0033 §5).** When `match` finds no tournament the player is allowed in, `missReason` walks the SAME filters in the SAME order (device target → window → device rules → entry, the last via `entryRefusal` in `src/utils/tournamentEntry.ts`, through which `entryAllowed` is defined) over the open games whose NAME matched and names the furthest one reached, with tournament/round/room. Null when nothing of that name is open to the player. It rides the Global result as `notCounted`, goes FIRST in the trail row's `reasons`, and is sent on the wire as `notCounted` (additive; also carries a `no_match` reason). **A new filter in `match` needs its step in `missReason` too.**
- **"Where your plays went" (W27.2, v2.183.0).** `GET /api/me/witness/plays` → `WitnessEvidenceService.recentPlaysForUser` reads the player's OWN trail (never the boards, so a play that landed nowhere is listed), groups one play's per-board rows on (device, played_at, score, table) and maps each outcome to `counted`/`already_counted`/`global`/`already_global`/`not_counted`/`deleted`/`not_recorded` (attempt reason codes through `ATTEMPT_REFUSAL_TEXT`). Rendered by `components/WitnessRecentPlays.tsx` under Account Settings → Arcaid Witness devices.
- **"Your scores go to" (W27.3, v2.184.0).** `components/WitnessScoresGoTo.tsx` (words in `lib/witnessScoresGoTo.ts`): on every room page (PublicLayout, under the event banner) one line per paired device from `GET /api/me/witness/routing?roomId=` → `WitnessService.routingForRoom`, which runs `deviceRoutesTo` on the device's EFFECTIVE target (`getDeviceTarget`) — never a FE copy of the rule, so the line cannot disagree with the ingest (`yes` / `one_tournament` / `entered_only` / `no` + `global_only`/`other_room`/`other_tournament`/`not_member`). On the home page under My Game Rooms, where each device sends (from `/api/me/witness/devices`). "Change" links to `/account/settings#witness-devices`.

## Witness score routing (P9b, v2.152.0; W26/W37, ADR 0032/0033)
- **Each PAIRED device carries its own designation** (`witness_devices.target_room_id` / `target_tournament_id` / `global_fallback`, migration 173), set at Account Settings → paired cabinets via `PATCH /api/me/witness/devices/:deviceId` — validated: the room must be one the player is a member of and the tournament must be in that room. **It NARROWS the candidate set, it does not route past the matching** — name and window still decide.
- **ONE pure rule, `deviceRoutesTo` in `src/utils/witnessRouting.ts`,** shared by ingest and the check-in lobby (v2.174.0 W26, v2.175.0 W37; ADR 0033 "room membership is tournament entry"):
  - **All my rooms is the DEFAULT** (no room, `witness_devices.global_only = 0`): every room the player is a member of, plus any tournament they were entered into directly.
  - one room → that room's games · one tournament → that tournament only.
  - **"Global Scoreboard only" is the explicit opt-out** (`global_only = 1`, ADR 0032).
  - **A joined Throwdown is reachable from every UN-pinned device**, Global-only included (room-less, so no device can be pointed at one — owner ruling 2026-10-25).
  - Migration 191 moved EVERY existing device to All my rooms (owner ruling 2026-10-26).
- **Then ONE "allowed in" test, `entryAllowed` in `src/utils/tournamentEntry.ts`,** shared with the typed gate `EventSubmissionGate`: a Throwdown needs a join, an event that requires check-in needs a participant row, anything else needs room membership (or a participant row). The device path skipping check-in was W36.
- **A play counts in EVERY tournament it matches.** `match` returns `targets` (one game per tournament, rounds first); `ingestNow` runs the per-board `landOn` for each and `combine`s; the wire answer's top level is the first landing and `landed[]` lists all. This replaced "two matches = no_match" and round-beats-rotation; ambiguity survives only INSIDE one tournament (that tournament is skipped) — two survivors there is never a guess.
- **Limited attempts across tournaments:** the start uses an attempt in EACH limited tournament (`attempts` unique on `(device_id, attempt_key, game_id)`, migration 192).
- **Lobby:** grades a device only when it routes to the event; otherwise `not_routed` ("Device not sending here").
- **Leftovers → the GLOBAL SCOREBOARD** (`originType: 'global'`, engine `vpx` / device from `provenanceFor(device_type)` — `atgames` for a cabinet, `pc` for the Castcade desktop companion — deduped on (player, catalogue game, score)), so a paired-then-forgotten cabinet still earns the player a personal record. This does NOT violate ADR 0016 P2's bar on `'sync'` reaching Global: that bars unknowable provenance, and a witness score's is exact.
- **`global_scores.global_game_id` is NOT NULL,** so a table missing from the catalogue cannot be recorded globally — reported as `no_match` with a reason, never invented. Same-named machines are told apart by the manufacturer/year parenthetical in the launcher's own display name.
- **A designated tournament that has FINISHED reads as ABSENT** (read-time expiry, no cleanup job), and `loadCandidates` ignores games of inactive tournaments entirely.
- **A REPEAT of a play that already landed answers like the first time (v2.167.1).** Before the attempt binding, the suppression check and the gate, `landedRepeat` looks for the SAME play in `score_history` (game row, room, tournament stamp, player, score, `source='vpx'`, `created_at` = the launcher's end time); inside `REPEAT_WINDOW_SEC` (120 s) it answers `ingested` writing nothing (trail outcome `duplicate`, pointing at the row). The Global path answers `global` for a row whose `submitted_at` is inside the window. Keyed on the ROW, never the trail (in the concurrent case the first run's trail lands after its row). An old replay (cabinet restart / re-pair) stays `duplicate`.
- **`ingest` chains one device's reports (the `inflight` map)** because the `log` dedup is SELECT-then-INSERT with no unique index, so same-tick copies would all write (prod 2026-10-22: four sender-side ingests per live score inside 2 s).
- **Activity log (G14, ADR 0037; detail in `scores-identity.md`).** Every ingest outcome except `duplicate` / `global_duplicate` (no row, owner 2026-11-07) writes its row from `trail` (room row only inside a room's tournament; Global / no_match / invalid are room-less); device rows go to `ActivityLogService.roomsForDevice` at write time. Never one row per heartbeat: `recordHeartbeat` logs only the online TRANSITION (after `HEARTBEAT_STALE_SEC`), `sweepDevices` the offline one (`witness_devices.offline_logged_at`; `info` unless `deviceMatteredInRoom` for that routed room, so a nightly power-off is never a problem) and "launched, no score arrived" (a session >= 60 s, exit >= 10 min old, no `witness_evidence` from the device between launch and exit + 10 min; once per session via `witness_observations.activity_checked_at`). A new device-facing writer writes its row too.
- **The check-in response carries `sendingTo`** so the cabinet prints where its scores go — the defence against a stale designation is that the player sees it before the round, not after.

## Integrity mode — Open play / Sanctioned play (v2.165.0, ADR 0027; Castcade ADR 0005, Castcade F3)
- **Columns.** `tournaments.integrity_mode` (`open` default | `sanctioned`) + `sanctioned_rules` (partial JSON; `normalizeSanctionedRules` in `src/utils/sanctionedRules.ts` fills defaults and clamps). **An update that OMITS the fields keeps them** — never reset a Sanctioned tournament from a form that predates the field. Per-game `games.required_vps_table_id` / `required_rom` / `required_fingerprint` (`PATCH /api/rooms/:roomId/tournaments/:id/games/:gameId/requirements`), migration 184.
- **Evidence.** The Castcade companion sends EVIDENCE with every score on `GET /witness/score` (`vps_game`, `vps_table`, `table_sha256`, `table_save_rev`, `ini`, `adjustments`, `build`, later `fingerprint`); `parseWitnessEvidence` — every param optional, a malformed one is DROPPED, never a 400; a cabinet sends none.
- **`evaluateSanctioned` is a pure function and the ONE evaluation** (ingest, the review page and the companion's F5 preflight must agree). It runs for EVERY tournament match in BOTH modes; the verdict is stored in `witness_evidence` (one row per witness score the ingest saw, every outcome, keyed to the `score_history`/`global_scores` row; no FKs) via `VpxScoreIngestService.trail`, best-effort.
- **The ONE gate:** a `flagged` verdict in a SANCTIONED tournament is not written to that board — the desktop is answered `not_sanctioned` + `reasons[]` + `fallback`, a CABINET is answered `no_match` (its own vocabulary; no evidence, no screen), and the play falls through to Global like an unmatched score. **Open play NEVER refuses;** room boards never filter or re-rank (the public `GET .../integrity` ships a `score_history.id → verdict` MAP for a badge, nothing else).
- **Rules:**
  - named table / stock physics (`stock === true`, no `difficulty_override`, no flipper override).
  - factory adjustments (+ `adjustments_allowed`, default `['Free Play']`); **no adjustments map = unverifiable = skipped, never failed** (291 of 383 maps have none).
  - known build as an **ALLOW-LIST, never "official only"**: `official` + `panasony` pass (owner ruling 2026-10-19 — the owner's own rig is Panasony), `nightly` behind `allow_nightly_builds`, `unknown` only with a `blessed_build_hashes` SHA-256; `cheat: true` always fails.
  - `min_tilt_sensitivity` (default 300; VPX 0–1000, HIGHER tilts sooner, VPX default 400, 0 = analog tilt off, applies only while `accel !== false`) / `max_accel_gain` (150 = VPX default) / `require_nudge_filter` (off).
- **Matching prefers `vps_game`:** `catalogueGame` resolves it to the `global_games` row, and that row's names (+ `games.global_game_id`, which only PINNED games carry — rotation/event rows leave it NULL) are tried before the device's names; the name match stays as the fallback.
- **Table/ROM catalogues.** `global_game_tables` (VPS `tableFiles[]`, `VpsImportService.syncTableFiles`, `GET /api/global/games/:id/tables`) feeds the runner's required-table picker. `global_game_roms` (migration 197, v2.193.0, W12) is filled from VPS `romFiles` (`romFiles[].version` is the PinMAME ROM id, the field the companion's seed reads) by `VpsImportService.syncRomFiles`, served at `GET /api/witness/roms` (public, versioned, ambiguous ROMs listed as such) and consulted by `VpxScoreIngestService` as a tier BEFORE the name fallback when a report names a `rom` and no usable `vps_game`. `GlobalGameRomService` is the ONE filter both read through; a ROM under two games is ignored, never guessed.
- **Admin UI (v2.166.0, F3 part 2).** Integrity section on `TournamentForm.tsx` (payload always carries `integrity_mode` + the full `sanctioned_rules`); per-tournament `IntegrityPanel.tsx` (required table picked from `GET /api/global/games/:id/tables` by the game's `globalGameId` = pinned id, else the exact-name approved catalogue row, else null; required ROM; evidence review); board badges on the public game page from the public integrity read (`lib/integrityBadge.ts`; the leaderboard read carries `tournamentId`).
- **`play_device`** (`pc` | `vr_headset`) on `GET /witness/score` from a DESKTOP witness sets the device axis (`provenanceFor(deviceType, playDevice)`); a cabinet's value is ignored. Item 12 (script baselines, preflight) is Castcade F5.
- **`engine` evidence (v2.168.0, Castcade hook 0.4.0):** what VPX had in force during the game, sampled inside the table; stored raw in `witness_evidence.engine` (migration 187). Rule `engine` under `require_stock_physics` (in-game change / live physics set / live difficulty ≠ file ⇒ fail; absent ⇒ skipped); the tilt rule prefers the live value. `engine.difficulty` > 1 is a 0–100 value from companion 0.2.12 and `parseEngineSample` divides it by 100 (v2.170.0); stored rows are re-parsed on read for display, their stored verdict is not re-evaluated.
- **`score_plausibility` (v2.170.0, companion ≥ 0.2.13):** how player 1's score moved (changes, largest jump, jumps off the ROM's step of 10, a `flag` sentence); stored raw in `witness_evidence.score_plausibility` (migration 189), shown on the Integrity panel. **FLAG ONLY, NEVER A GATE** (owner ruling 2026-10-25): no rule in `evaluateSanctioned` reads it, and it alone never makes a score "evidenced".
- **`quit`/`quit_ball` (v2.189.0, W49, castcade B16)** are stored on `witness_evidence` (migration 196; `parseQuitEvidence` in `src/utils/quitEvidence.ts` — NULL unknown, malformed dropped, never a 400) and shipped as a SEPARATE `quits` map on the public integrity read (`WitnessEvidenceService.quitMap`, apart from `verdicts` because a verdict may be withheld while the quit fact is known). Rendered as "Quit on ball N" on the game page, the Integrity panel, the history-expand rows and Where your plays went (W53). **FLAG ONLY, NEVER A GATE** — a quit game still counts and still uses its attempt.
- **Cabinet 1.0.8 restarts (W64, v2.198.0):** a game abandoned by a hold-Start restart is sent as its own score with `reason=restart`, `quit=1`, `quit_ball=<ball in play>`; its scored attempt row carries note `restart` (the `:r<i>` rows from `restarts=N` stay for older builds). Nothing gates `quit` on device type.
- **The badge is withheld when there is nothing to judge (v2.166.2).** `VpxScoreIngestService.badgeVerdict` decides what the trail STORES for a score that LANDED: a CABINET never gets a verdict (whatever a later cabinet build sends — VPS ids, table/script/ROM/engine hashes — is stored but NOT run through the desktop rules, which would fail "settings/builds were not reported" and paint every cabinet score Flagged; a cabinet evidence profile in `evaluateSanctioned` is the item that lifts this), and neither does a desktop that sent NO evidence (Castcade < 0.2.5). The trail row is still written (outcome, raw fields, evidence) and the Sanctioned gate is unchanged — the `not_sanctioned` refusal row KEEPS its flagged verdict for the runner's review. "No evidence" is an absence of badge, never a badge of absence (`integrityBadge.ts`).

## Limited attempts (v2.167.0, ADR 0029)
- **`tournaments.max_attempts` (NULL = unlimited) makes a tournament witness-only.** Attempts are counted per game START in `attempts` via `AttemptService` (desktop: `GET /witness/attempt` + `attempt=<key>` on the score; cabinet: each report is the attempt, key `cab:<started>`); the score and attempt calls share `VpxScoreIngestService.match`.
- **Every manual submit path must call `checkAttemptLimitSubmission` beside its event gate** — a new submit path that skips it lets typed scores onto a limited board.
- **Host corrections (v2.203.0, W68).** A SCORED attempt can be voided (route body `deleteScore: true` also deletes its score through `ScoreHistoryService.deleteEvent`, after the void). An `over_limit` attempt can be REINSTATED (`AttemptService.reinstateAttempt`) once the player's other non-void rows on that table are under the limit — it lands through the ingest's own `VpxScoreIngestService.writeBoardRow` with no second Global row; a desktop over-limit start never stored its score and is refused.
- **Otherwise `void` and `over_limit` are terminal** (`bindScore` and the cabinet report path refuse a replay of either), and no score delete touches `attempts`.
- **An `over_limit` row USED no slot (v2.217.1, W85).** Every used count — `insertAtomic`'s next-start decision, `usedByGame` / `usedByPlayer`, the reinstate room check, the FE `summarizeAttempts` — reads `USED_STATUS_SQL` (`counted` / `scored` / `unreported`). A hand-written `status <> 'void'` count is the bug that printed "15 of 5", refused the start after a void and blocked Reinstate (incident 2026-11-01). Over-limit rows still number past the limit (`MAX(limit, used) + k`).
- **Pre-window starts count (v2.178.0, W38, ADR 0033 §3–4).** A desktop play that STARTED before the window and ended inside it is counted at score time (`bindScore`'s `windowStartTs`, note "started before the window") instead of refused as `unreported`.
- **`tournaments.require_attempt_start`** (host setting, off by default): plays go to Global and use NO attempt until the player presses Start attempts for that table (`attempt_starts`, one row per player per games row, first press kept).
- **`GET /api/witness/attempt-start` (v2.188.0, W45) is the device-token twin of the web button:** it derives its games from `VpxScoreIngestService.openLimitedGames` (so it can never start a table a play would not land on; a named table narrows them through `match`) and writes `source='device'` through the same `AttemptService.startAttempts`.
- **The rule is `playIsStarted`** (the GAME's start at/after the press), checked BEFORE any attempt row is written, in three places: the score ingest's limited block (`not_started`), `WitnessService.recordAttempt` (answers `no_match` + reason, no new wire status) and so the cabinet's report path. The web button (`AttemptService.startForPlayer`) applies `entryAllowed` like a device play. Check-in and Start attempts are independent.
- **The button is also on the room scoreboard (v2.197.0, W56):** every card style carries a Start attempts strip above its footer for the viewer's unstarted tables, fed by ONE room read `GET /rooms/:roomId/attempt-starts/me` whose game set is `VpxScoreIngestService.roomLimitedGames` (sharing `enteredLimitedCandidates` with `openLimitedGames`, so a card can never offer a table a play would not land on); the "Your scores go to" strip lists the tables still to start.
- **That room read returns EVERY open limited game the viewer is allowed in (v2.210.0, W82)** (additive `limit`/`used`/`left`/`requireStart`): the press control and the "needed on" line filter on `requireStart`, and `CardAttemptsLeft.tsx` paints "N attempts left" top-left of the viewer's OWN card in all four styles — nothing for a guest, the kiosk or the admin preview, which have no `CardAttemptStartContext` provider (`pages/Scoreboard.tsx` is the only one).
- **`openLimitedGames` takes `playDevice` (v2.191.0, W51),** so the attempts line and the device press apply the same device-exclusion rule as `match`.

## Invite-only tournaments (v2.179.0, W39, ADR 0033 §6)
- **Columns.** `tournaments.entry_mode` (`members` default | `invited`) + `entry_methods` JSON `{link, request}` + `invite_code` (migration 194). `TournamentEntryService` owns the roster (`tournament_roster`, canonical ids), the invite code, the request queue (`tournament_entry_requests`) and the typed gate.
- **The roster is NOT `tournament_participants`** (that is the event CHECK-IN list); an invite-only event with check-in needs both — `entryAllowed` takes `entryMode` + `onRoster`.
- **Enforcement points:**
  - `checkRosterSubmission` beside `checkAttemptLimitSubmission` at every manual submit path (`403 NOT_ON_ROSTER`; **a new submit path needs both calls**).
  - the device candidates (`on_roster` + `entry_mode` in `loadCandidates`; a roster spot routes as a direct entry).
  - `EventService.checkIn` (self check-in to an invite-only event throws `NotOnRosterError`; the host's add puts the player on the roster).
  - the Start attempts button.
- **`invite_code` is a secret:** `TournamentService.getAll` and `EventService.getEvent` strip it — **a new public read of a whole tournament row must too.**
- **Links are `/api/tournament-invites/:code` + page `/tournament-invite/:code`,** deliberately NOT `/invite/:token` (the room-admin invite).
- **UI:** host `components/RosterPanel.tsx`; player `components/EntryNotice.tsx` (game + event pages), `pages/TournamentInvite.tsx`.

## Witness flag mode (v2.169.0, ADR 0031) — the one place a verdict gates
- **`tournaments.witness_flag_mode` (`prevent` default | `flag`).** In an EVENT under `prevent`, a `flagged` score (game started before the round opened) is left out of the round board and the player's best UNflagged score ranks; the flagged one rides `notCounted` for the event page.
- **It acts at standings time in `EventResultService.getRoundBoard`** (which therefore judges EVERY row of the round, not just each player's best) — never at ingest, never by deleting — so `flag`, Re-verify and the frozen result all recompute from the same rows.
- **Room board and game page derive an event round's rows at READ time** from `EventResultService.getRoundBoardDetail` (`LeaderboardService.getEventRoundOverlays`, v2.190.0, W22), so they rank as the standings do and ship `witness` per row plus `notCounted`/`witnessByHistoryId` per game — **never in `leaderboard_cache`**; Global is untouched.
- **The overlay is applied INSIDE `LeaderboardService.getForGame` / `getForGameByProvenance` / `getForGameByPlatform` (v2.192.0, W52),** so Discord `/list-scores`, the `/submit-score` rank reply and the chat `leaders` / `my_rank` actions rank an event round as the standings do.
- **Stats exclusion:** `StatsService.getGameStats` (avg, unique players, all-time high) and `getGamePlayerRankings` take `excludeHistoryIds` (the game page passes `EventResultService.preventedHistoryIds`); `getGameStats`' `recentResults` names a finished round's round-board rank-1 as its winner.
- **Read the column only through `normalizeWitnessFlagMode`** (`src/utils/witnessFlagMode.ts`).

## Cabinet log pull and self-update (v2.246.0, W99/W100, ADR 0040; cabinet 1.1.0)
- **The heartbeat answer is the only way to reach a cabinet.** It carries two OPTIONAL flat strings, `logs` (a 32-hex request id) and `update` (a dotted version), built by `witnessHeartbeatExtras`: each lookup is best-effort and a field is omitted, never empty. The cabinet reads the answer with a naive `"key":"value"` extractor, so nothing with a quote or backslash may ever go in a heartbeat field.
- **The cabinet decides what leaves it.** `POST /api/witness/logs` takes one raw ustar body (16 MiB, `express.raw` on that route only, device auth BEFORE the body is read via `requireWitnessDevice`); the allow-list is compiled into the cabinet app. Never add a parameter that names a file or a path.
- **A log bundle is its player's.** `WitnessLogService` keys every read on the caller AND the id; the id alone opens nothing. Only the player's `POST /me/witness/log-requests/:id/share` sets `shared_at`; the super-admin routes (`GET /admin/witness/shared-logs[/:id/download]`) read ONLY shared rows, so an unshared bundle is never readable by an admin route. Lifecycle: `pending` 15 min → `expired` (lazy, no timer) · `ready` 7 days (30 from `shared_at`) · `revokeDevice` purges; the player's Remove deletes a shared copy too. Files: `data/witness-logs/<id>.tar`, served through gzip.
- **THE OFFER RULE is one pure function, `offeredRelease`** (`WitnessReleaseService`): cabinet (`atgames`) only, `auto_update` = 1, a reported version, the highest `stable` release (plus `beta` when `test_builds` = 1) numerically above it; `draft` goes to nobody. The heartbeat, `/witness/app/release`, `/witness/app/download` and the devices list all read it. Versions compare through `compareVersions` (`1.0.10 > 1.0.9`), never as strings.
- **A release is refused unless its signature verifies** (`verifyReleaseSignature`: Ed25519 over `"AW1 <version>\n"` + the ELF bytes, public key in `src/utils/witnessReleaseSignature.ts` and compiled into the cabinet app — change both or no cabinet installs anything). The private key is `~/.arcaid-witness/release-signing-key.pem` on the owner's PC and nowhere else; `npm run witness-release -- sign` is its only reader.
- **`:version` and request ids touch the filesystem** — validate through `isReleaseVersion` (strict triple) and `isLogRequestId` (32 hex) before building a path.
- **The update switches are the player's:** `auto_update` / `test_builds` reset to the defaults when a device is paired to another account (the pairing upsert).
- Log pull and updates are not score paths and write no activity row; release changes and log requests write `audit_log` (`witness_release.*`, `witness_log_request`). A share DMs the operator (`OpsAlertService`; a label, never an id).
- **Pair by phone (W102, v2.247.0):** `/witness/pair/start` gives a code + poll secret (stored as SHA-256); the player approves; the pairing HAPPENS at the cabinet's `/witness/pair/poll`, so the token is never stored. Both flows share `assertPairingAllowed` (at approve AND poll) and `writePairedDevice`: never copy them. Never log the code, secret or token.
- **Kit** (`WitnessKitService`): ALWAYS the highest `stable` release + repo-root `witness-kit/`. **Health:** `listDevices` adds `watching` (`HEARTBEAT_STALE_SEC`; `unknown` = never heartbeats); the reminder's cabinet line keys on it.

## Castcade match relay (v2.242.0, W8.4, ADR 0039)

`src/api/matchRelay.ts` (`match:host` / `match:join` / `match:relay` / `match:lock` / `match:leave`, registered per socket by `initWebSocket`) carries Castcade's match control frames between a host and its clients so the host forwards no port. Rules: **`data` is opaque** (a string, 256 KB cap; never parse, log or store it); **star topology** (client → host only, host → one named peer; never fan a frame out to the room); **auth is `WitnessService.verifyDevice`** on every host / join, fail closed, and again at most once a minute per seated socket on its next frame (a revoked device loses its seat); **the wrong-code lockout is per device, never per IP** (an address is shared; the IP has a raw attempt cap only); **`match:lock`** (host only) refuses devices that never held a seat, and the room's set of seated device ids is never sent to a socket; **in memory, one process** (no table; a second ArcAid process breaks it, see the ADR). The room key is the invite code; the roster check (W8.2 / W8.3) plugs into `admitJoin`. The wire contract is shared with the Castcade companion: do not rename an event, an ack field or an error word without changing Castcade in the same step. It is not a score path and writes no activity row.

**The join link page (W96, v2.243.0).** `GET /castcade/join/<invite>` (`src/api/castcadeJoin.ts`, mounted by `mountCastcadeJoin` BEFORE the SPA static + catch-all) is the https door to the companion's `castcade://join/<invite>`. Rules: **server-rendered, never an SPA route** (crawlers run no JS; no auth bootstrap); **the module imports no logger and no database** (an address invite holds the host's public IP; never log `req.originalUrl` there); **only what `parseJoinPath` passed reaches the page, escaped; the 404 is a constant**; **the OG tags are identical for every invite**; the invite shapes mirror castcade `companion/src/main/deep-link.ts` (change both); `sw.js` returns early for `/castcade/` so the navigation is never cached.
