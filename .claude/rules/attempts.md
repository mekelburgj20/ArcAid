# Limited attempts and Practice mode — rules

Detail for attempt counting, host corrections, Start attempts and Practice mode. The ingest they plug into (`VpxScoreIngestService.match`, routing, entry, the trail) is in `witness.md`: read it before changing which play counts where. Cross-cutting invariants live in the root CLAUDE.md.

## Limited attempts (v2.167.0, ADR 0029)
- **`tournaments.max_attempts` (NULL = unlimited) makes a tournament witness-only.** Attempts are counted per game START in `attempts` via `AttemptService` (desktop: `GET /witness/attempt` + `attempt=<key>` on the score; cabinet: each report is the attempt, key `cab:<started>`); the score and attempt calls share `VpxScoreIngestService.match`.
- **Every manual submit path must call `checkAttemptLimitSubmission` beside its event gate** — a new submit path that skips it lets typed scores onto a limited board.
- **Host corrections (v2.203.0, W68).** A SCORED attempt can be voided (route body `deleteScore: true` also deletes its score through `ScoreHistoryService.deleteEvent`, after the void). An `over_limit` attempt can be REINSTATED (`AttemptService.reinstateAttempt`) once the player's other non-void rows on that table are under the limit — it lands through the ingest's own `VpxScoreIngestService.writeBoardRow` with no second Global row; a desktop over-limit start never stored its score and is refused.
- **Otherwise `void` and `over_limit` are terminal** (`bindScore` and the cabinet report path refuse a replay of either), and no score delete touches `attempts`.
- **An `over_limit` row USED no slot (v2.217.1, W85).** Every used count — `insertAtomic`'s next-start decision, `usedByGame` / `usedByPlayer`, the reinstate room check, the FE `summarizeAttempts` — reads `USED_STATUS_SQL` (`counted` / `scored` / `unreported`). A hand-written `status <> 'void'` count is a bug (it printed "15 of 5" and blocked Reinstate). Over-limit rows still number past the limit (`MAX(limit, used) + k`).
- **Pre-window starts count (v2.178.0, W38, ADR 0033 §3–4).** A desktop play that STARTED before the window and ended inside it is counted at score time (`bindScore`'s `windowStartTs`, note "started before the window") instead of refused as `unreported`.
- **`tournaments.require_attempt_start`** (host setting, off by default): plays go to Global and use NO attempt until the player presses Start attempts for that table (`attempt_starts`, one row per player per games row, first press kept).
- **`GET /api/witness/attempt-start` (v2.188.0, W45) is the device-token twin of the web button:** it derives its games from `VpxScoreIngestService.openLimitedGames` (so it can never start a table a play would not land on; a named table narrows them through `match`) and writes `source='device'` through the same `AttemptService.startAttempts`.
- **The rule is `playIsStarted`** (the GAME's start at/after the press), checked BEFORE any attempt row is written, in three places: the score ingest's limited block (`not_started`), `WitnessService.recordAttempt` (answers `no_match` + reason, no new wire status) and so the cabinet's report path. The web button (`AttemptService.startForPlayer`) applies `entryAllowed` like a device play. Check-in and Start attempts are independent.
- **The button is also on the room scoreboard (v2.197.0, W56):** every card style carries a Start attempts strip above its footer for the viewer's unstarted tables, fed by ONE room read `GET /rooms/:roomId/attempt-starts/me` whose game set is `VpxScoreIngestService.roomLimitedGames` (sharing `enteredLimitedCandidates` with `openLimitedGames`, so a card can never offer a table a play would not land on); the "Your scores go to" strip lists the tables still to start.
- **That room read returns EVERY open limited game the viewer is allowed in (v2.210.0, W82)** (additive `limit`/`used`/`left`/`requireStart`): the press control and the "needed on" line filter on `requireStart`, and `CardAttemptsLeft.tsx` paints "N attempts left" top-left of the viewer's OWN card in all four styles — nothing for a guest, the kiosk or the admin preview, which have no `CardAttemptStartContext` provider (`pages/Scoreboard.tsx` is the only one).
- **`openLimitedGames` takes `playDevice` (v2.191.0, W51),** so the attempts line and the device press apply the same device-exclusion rule as `match`.

## Practice mode: a player pauses their attempts (v2.266.0, W126, ADR 0043)
- **The rule: a play is practice when its START falls inside one of the player's pauses on that table** (`attempt_pauses`, migration 223; `playIsPractice`). **A pause only looks forward:** `paused_ts` / `resumed_ts` are the SERVER's clock at the press, never backdated, never edited. A game already running when Pause is pressed stays an attempt; a practice game still running at Resume stays practice. Never add a path that sets either time from a device or a form.
- **Host setting `tournaments.practice_games`:** NULL = players cannot pause (the default, every existing tournament), 0 = unlimited, N = N practice games per player per `games` row for the table's whole run. Read it only through `normalizePracticeGames` (`src/utils/practiceGames.ts`); an update that omits it keeps it. Offered on any limited tournament, events included (owner 2026-11-24).
- **A practice game is an `attempts` row with status `practice`**, decided in the SAME statement as the limit (`AttemptService.insertAtomic`): in a pause AND practice offered AND the allowance not used up. It is numbered in its own sequence (practice 1, 2, 3), beats a forced `unreported`, and is **never in `USED_STATUS_SQL`**. A new reader that lists statuses must name `practice`: `recordStart` used to answer every row that was not counted or scored as `over_limit`.
- **The pause ends itself when the last practice game STARTS** (`closePauseAtCap`, `ended_by = 'cap'`); the next start is an attempt. The rule does not depend on that row closing (`insertAtomic` tests the allowance itself), so `practiceStateFor` reads an open pause with nothing left as not paused.
- **Decided once, when the start is first seen, and always against the play's OWN start time** (the device's clock, like `playIsStarted`), never the moment the call arrived: a start call held back until the player saw a bad game and pressed Pause would otherwise be filed as practice. A desktop's start call files the row; the later score binds to that row and is never re-decided (`bindScore` → `practice`). A cabinet reports after the fact, same test. Restart rows (`:r<i>`) inside a pause are practice games too.
- **A practice play never reaches the tournament board.** It is refused with reason `practice` exactly like `not_started`: Global fall-through, trail outcome `attempt_refused`, but its activity row is `witness_practice`, severity `info` (it is what the player asked for). The row keeps its score (W126.2 would need it). No host "count this practice play" exists (owner 2026-11-24).
- **On the wire** the attempt call answers `no_match` + `reason` + an additive `practice: {n, of, remaining}` (no new status; `of` 0 = unlimited). `ATTEMPT_REFUSAL_TEXT.practice` must not open with the `not_started` words: the Castcade companion recognises that reason by its opening words. A start that used an attempt in another tournament is answered as that attempt.
- **The press is web only** (`POST .../games/:gameId/attempt-pause` and `/attempt-resume`, `AttemptService.pauseForPlayer` / `resumeForPlayer`). Pause shares `playerGameRow` + `playerEntry` with Start attempts and refuses `NOT_OFFERED` / `NOT_OPEN` / `NOT_ENTERED` / `NOT_STARTED` / `NO_ATTEMPTS_LEFT` / `NO_PRACTICE_LEFT`; Resume is never refused for a closed table. The FE's `canPausePractice` (`lib/attemptStarts.ts`) mirrors those checks: change both.
- **The paused state is loud on purpose** (a player who forgets to resume plays real games as practice): the card strip and badge (`CardAttemptStart`, `CardAttemptsLeft`), the game page box, the amber "Practice mode is on for" line in `WitnessScoresGoTo` (keyed on the pause's time through `practiceNoticeKey`, so a dismissal hides that pause only), the cabinet line (`attemptsLeftLine` → `PRACTICE MODE`) and tile card (`practice`). The runner sees practice rows and "In practice mode now" on the Integrity panel (`pausedNow`); voiding a practice row gives the practice game back.
