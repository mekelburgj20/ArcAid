# Admin UI / React front end — rules

Loads when you touch any front-end file under `admin-ui/`. Cross-cutting invariants live in the root CLAUDE.md; this file is the detail for this domain.

## Structure and routing
- **Admin UI (`admin-ui/src/`)** is React 19 + Vite (ESM). All HTTP goes through `lib/api.ts` (relative `/api/` paths — never hardcode localhost).
- **Three layouts:** `SuperAdminLayout` (`/admin/*`), `RoomAdminLayout` (`/:slug/admin/*`), `PublicLayout` (`/:slug/*`). Plus standalone global pages (`/scoreboard`, `/games/:id`, `/friends`).
- **There is NO public `/catalogue` route.** `GlobalCatalogue` is a super-admin tool under `/admin/catalogue`; public catalogue browsing happens on `/scoreboard`.
- **Contexts.** Room-scoped pages get `roomId/roomSlug/roomName` from `RoomContext`. Public pages get viewer auth from `ViewerAuthContext` (auto-refreshes player tokens within 5min of expiry).
- **Global game page `/games/:id` (`GlobalGameDetail`)** ranks each player ONCE, by their best. Clicking a row expands all of that player's scores via `GET /api/global/scoreboard/:globalGameId/players/:playerKey/scores`, keyed on the board row's `player_key` — the SAME partition expression the board collapses on, shared in `GlobalLeaderboardService` so the two can't disagree about who a player is. Clicking a score toggles a score-over-time chart (`components/ScoreHistoryChart.tsx`, hand-rolled SVG, theme tokens only) that shares that one fetch (v2.157.0).
- **Display settings (G34a, v2.274.0)**: a live panel (`components/displaySettings/`, its own chunk; `DisplaySettingsHost` opens it on `UserMenu`'s `open-scoreboard-prefs` window event). It edits this device's card set only (`prefsDevice()`, `lib/displaySettingsLive.ts`), sends each change as `display-settings-live` (the whole map) and POSTs every key 500 ms later. Signed out (G34c, v2.276.0) it opens from `DisplaySettingsButton` (sliders, beside the sun/moon) and the card set is `arcaid-scoreboard-prefs-<device>` in localStorage, no `/api/me` call.
- **Public slug matching is case-insensitive.**
- **Every room read from a public page goes through `lib/roomFetch.ts` (v2.241.1, D19).** In an `approval` room `roomVisibilityGate` refuses a read without the viewer's login, and pages turn a refusal into an empty list, so a bare `fetch` of an `/api/rooms/:roomId/...` path is a blank page for members. `roomFetch` attaches the stored player token at call time (signed out it is the bare call). Only `/portal` and `/scoreboard-config` answer before the gate. `lib/__tests__/roomFetch.test.ts` fails on a bare room GET with no options; a call that passes its own `headers` must carry the token itself.

## Scoreboard rendering
- **Style+Theme dispatch.** `SCOREBOARD_STYLE` (banner/showcase/minimal) + `SCOREBOARD_THEME` (showcase variants live in `lib/scoreboardThemes.ts`) → `CardRouter.tsx` selects `BannerCard`/`ShowcaseCard`/`MinimalCard`. Config derivation in `lib/scoreboardConfig.ts`: `deriveScoreboardConfig` is the new path; `deriveCardProps` is the legacy fallback. Live preview on the admin Leaderboard page is rendered inline (CSS scale-transform); the old standalone `ScoreboardPreview` component was removed as dead code (2026-08-21).
- **Manual card order is a self-invalidating override (v2.118.0).** Room scoreboard order = `COALESCE(g.display_order, t.display_order, 9999), g.start_date` (`LeaderboardService.getActiveLeaderboards`; `games.display_order` has NO writer — leave it that way). An admin drag on the admin Leaderboard page stores `game_room_settings.LEADERBOARD_CARD_ORDER` (NOT a `SCOREBOARD_*` key — that prefix is auto-public via `/scoreboard-config`) with a fingerprint of each tournament's `display_order` + sorted ACTIVE game ids.
  - `CardOrderService.applyCardOrderOverride` (pure) applies it at READ time: any fingerprinted tournament's `display_order` changed → whole override ignored; a tournament's ACTIVE set changed → only its ids drop (rotation by any path — no hooks in TournamentEngine/TimeoutManager, don't add any); slot-fill merge for the rest.
  - **Save and read MUST compute the fingerprint through the same `loadCurrentState`** or the override self-destructs on the next read.
  - Arrows (`HorizontalScrollNav`, fixed z-40 portalled to body) are off on the admin page (`hscrollArrows={false}`) — they cover the rail column by construction.
- **Past-games piles (v2.236.0, B23).** The public board folds each tournament's retained COMPLETED cards into one pile behind its LAST live card: `lib/historyPiles.ts` is the grouping rule (keyed on the board's `tournamentId`, never the name; newest first by `endedAt`), `components/scoreboard/HistoryPile.tsx` draws it. Only `pages/Scoreboard.tsx` passes `historyPiles`; the admin Leaderboard and kiosk stay flat, and a search flattens. Stacked cards are real cards, `inert` + `aria-hidden`, clipped to the live card's MEASURED height (a rail/grid slot is as tall as the row's tallest card).
  - Pinned-open state is per USER: `scoreboard_prefs.pinnedPiles` via `/api/me/pinned-piles` (players), `arcaid-pinned-piles` localStorage (guests + first paint), `hooks/usePinnedPiles.ts`. **Every `scoreboard_prefs` writer round-trips `parseDevicePrefs`, so a new top-level key must be defaulted there** or a theme or device save silently drops it.
- **Past results (v2.238.0, B24).** `lib/tournamentLinks.ts`'s `tournamentResultsPath(slug, tournamentId, runGameId?)` is the ONE builder of links to a tournament's results (`/:slug/tournaments/:id`; `?run=<gameId>` opens one run). The server's copy (Discord posts) is `tournamentRunUrl` in `src/utils/publicLinks.ts`: change both together. Users: the card chip (`tournamentChipLink` -> the surface's `chipLinkTo`; the public board and admin Leaderboard pass it, the kiosk never does), the pile spine, History rows, the Lobby `tournament_results` item (`metadata.gameId`).
  - `TournamentDetail` opens on Runs (`/history?tournament_id=`, a row opens `/leaderboard/:gameId`); `?view=tables` is the merged per-table boards. A `?run=` with no `page` asks the server for the page holding that run; an explicit `page` never jumps. History keeps `?tournament=&type=&page=` in the URL and takes its type options from the room's own tags.
  - A finished card's timer slot shows `cardTimerText` ("Ended Tue, Nov 3" from `endedAt`), behind the same Show-timer setting.
- **Table art and avatars on results lists (v2.240.0, B25).** History, the tournament page, the player page and the Stats page draw `components/GameArt.tsx` (thumbnail; initials tile when there is no art) and `PlayerAvatar`. The server ships the art: `GameArtService` is the ONE rule (approved catalogue row by name; local, wheel, remote; the art a card falls back to), as `image_url` on rows or a `gameArt` map read through `lib/gameArt.ts`'s `gameArtFor`. Avatars ship beside names, resolved at read (`resolveProfiles`), never baked into a cache.
- **Run cards, a week at a time (v2.241.0, B26).** History and the tournament page's Runs view are ONE component, `components/results/RunFeed.tsx` (shared `RankLine` beside it): `GET /:roomId/history?week=N&standings=1`, week 0 = the seven days ending at the newest run in the filter (never "now"), `?run=` without `week` = the server picks that run's week; standings open by default, Collapse all / Expand all in `arcaid-results-collapsed` localStorage. Grid columns are `minmax(0,1fr)` or a long name pushes a card past a phone's edge. Results pages share `lib/pageLayout.ts` `RESULTS_PAGE` for their width.
- **Every ranking card links its full standings (B29, v2.254.0).** `RankingGroupCard` shows the top `RANKINGS_TOP_N`; its `slug` prop (from `ScoreboardSurface`, through `RankingsRow`/`RankingsColumn`) puts "Full standings →" to `/:slug/rankings/:groupId` (`pages/RankingsFullStandings.tsx`) in every style's footer. No slug or no ranked players, no link.
- **Style catalogue is global** (shared across rooms). Per-game overlay via `logo_style_id` + `bg_style_id` on `games` and `game_room_game_library`. Resolution: `effectiveBgId = bgStyleId || catalogueStyleId`.
- **Score abbreviation:** scores ≥1T render as `X.XT` with full value in tooltip.
- **Score toast:** WebSocket `score:new` carries `{ gameId, gameName, playerName, score }`; Scoreboard shows slide-down toast.
- **Image upload limit** 30MB. Formats PNG/APNG/JPEG/WebP. APNG animates natively in `<img>` tags.

## Live pages
- **Live pages must also recover when the socket does NOT deliver (v2.154.0).** `hooks/useLiveRefresh.ts` refetches on RE-connect (room membership is per-connection; a re-join of `room:<id>` on `connect` reloads nothing by itself), on visibility / `pageshow` / window `focus`, and on a 60s poll skipped while `document.hidden`. One 5s throttle across all three. `pageshow` is required because iOS bfcache fires neither a visibility change nor a socket event; `focus` because a desktop alt-tab fires no visibility change.
- **Any new page that calls `socket.emit('join:room', ...)` needs this hook too** — the five are Scoreboard, KioskScoreboard, GameDetail, the admin Leaderboard and the public Lobby (for `season:poll`). The hook owns only the recovery; each page keeps its own event handlers and decides what to reload.
- **A load that fails for now tries again by itself, and a page shows its empty text only after an answer (G31, v2.265.4).** `lib/loadRetry.ts` is the rule: a thrown fetch, 408, 425, 429 and any 5xx mean "ask again" (`isTransientStatus`); 401, 403 and 404 are answers. The waits rise 1, 2, 4, 8, 15, 30 s, or follow the server's `Retry-After` (the limiter sends it with a 429). `hooks/useRetryingLoad.ts` binds it: `{ load, phase }`, with `phase` `loading` (no answer yet), `retrying` (no answer and a try failed) or `ready`; a failed RELOAD stays `ready`, keeps what is on screen and retries quietly. The hook starts nothing: the page's effect, its socket handlers and `useLiveRefresh` call `load()`, and the hook is declared above the effect that first calls it. On it: the Scoreboard's look, board and rankings, the nav's room branding, the kiosk's look and board, and since G32 (v2.265.7) the first page of the Room Scores and Global tabs, the Lobby's feed and three content zones, the ticker's seed, the Stats page's reads, Picks' tournaments, game list and pick status, GameDetail's `stats/game` and board list, the landing page's sections (G35c). `ScoreboardSurface` takes `boardPhase` (default `ready`): "Loading games...", then "Couldn't load the scores" with Try now, and "Waiting for active games..." only for a room that answered with none. The room lookup has the same split: `getPortal` rejects with `PortalUnavailableError` for a failure-for-now, and `getPortalPatiently` waits it out (`PublicLayout`, `usePickAwardEnabled`, the kiosk), so "Room not found" is only ever a definite answer; a test that mocks `lib/portal` mocks `getPortalPatiently` too. Never write `if (res.ok) setX(...)` inside `catch { ignore }` for a page's main load: that is the silent empty room. The message is ONE component, `components/LoadFailedNotice.tsx` (`what`, `onRetry`, `testId`), never a page's own markup. A paged list retries its first page only: Load more keeps the rows and its button on a failure, and drops an answer that arrives after the query changed. An ok answer is stored only when it has the shape the render needs (`Array.isArray`), otherwise `onOk` throws and it is retried (a refusal's JSON error body stored as the game list was the Picks crash). A page that stays mounted across rooms (the Lobby, the ticker in the layout) clears its rows on a definite refusal, inside `request` (`!r.ok && !isTransientStatus(r.status)`), or the new room shows the last room's rows. Still read once: GameDetail's community scores, tips, player rankings and ratings; Picks' alerts, owned tables, members and disposition.

## Room-page notices (W83, G13)
- **The notices are rendered once by `PublicLayout` into a stable node that each room page places after its own header with `<RoomNoticeSlot />`** (`components/RoomNoticeSlot.tsx`; G13, owner 2026-11-25: the room's name and tabs first, then the notices in a row on the content's left edge, side by side from `sm`, stacked on a phone, nothing floating over content). `NotificationNudgeBanner`, `EventBanner` and `WitnessScoresGoTo` stay mounted in the layout, portalled into one container node that never changes, so they never remount across navigation (the Witness toast fires from `WitnessScoresGoTo`'s own read); the layout only moves that DOM node into the registered slot, or into a fallback wrapper at the top of the content when the page has no slot. **A new room page must place the slot** (right after its title block and tab row, inside the content's width wrapper; exactly one mounted at a time, the last to register wins: on the Scoreboard it is under the search + tabs row on Tournaments and inside `RoomScoresView` / `GlobalScoresView` under theirs). A new notice item uses `w-full sm:w-auto sm:max-w-sm` and goes through `DismissibleNotice` + `lib/roomNotices.ts`. The container's bottom margin applies only while it holds something (`[&:not(:empty)]:mb-4`); a slot that adds its own spacing keys it on `[&:has([data-testid=room-notices]:not(:empty))]`.

## Score entry and provenance memory
- **Provenance is remembered, per-game before global (v2.149.0).** `arcaid_last_provenance:<gameKey>` (JSON `{engine, device}`, checked FIRST) → `arcaid_last_engine` / `arcaid_last_device` (the global "my rig" keys; the device one dates to v2.53.0) → auto-lock when only one option fits → empty. Room targets key on `(roomId, lowercased game name)`, NOT a game id — a tournament game row is recreated on every rotation, so an id-keyed memory would forget exactly when the table comes round again.
- **Every remembered value must be tested against the same exclusion-filtered option list the dropdown renders** (`allowedEngines` / `allowedDevicesForEngine`). A membership test against the unfiltered list submitted `pc` while the `<select>` displayed "AtGames Cabinet" (v2.95.1).
- **Score ENTRY is comma-grouped (v2.149.0).** `admin-ui/src/lib/scoreInput.ts` — the sheet's `score` state holds the FORMATTED string so `lib/caretEdit`'s splice helpers and the browser's `selectionStart` index the same thing the player sees; every numeric read goes through `digitsOnly` first.
  - Grouping is done by string, not `toLocaleString`, so it stays exact past `MAX_SAFE_INTEGER` and cannot pick up a locale whose separator disagrees with `formatScore`.
  - Caret positions are carried across a re-group as a DIGIT COUNT (`reformatScoreEdit`), because inserting a digit into `999,999` also shifts every separator.
  - The field is `type="text"` on desktop too — `type="number"` refuses a value containing separators and is the one input type whose `selectionStart` throws.
  - `formatMagnitude` prints the plain-language echo ("6.66 billion", truncated never rounded) that is the actual defence against an extra digit.
- **The sheet is `Dialog` with `sheet` (G23d, v2.272.0):** only its top drags; each phase (`.sheet-phase`) and the keypad footer carry `data-base-ui-swipe-ignore`.

## Themes
- **Themes:** 11 themes in CSS variables (10 `.theme-*` classes + the no-class default `dark`, labelled "Arcaid" and drawn in the logo's colours since v2.263.0, G29) — the ONE list is `THEME_IDS` in `admin-ui/src/lib/themeIds.ts`, which `THEMES` (picker), `ALL_THEME_CLASSES` (class stripper) and the API's Zod enum are all derived from. Every dark theme sits on a real colour, not near-black; High contrast is black on purpose (no glow, no background image).
- **Dropped ids map through `LEGACY_THEME_MAP`** in that same module (FE `lib/themeIds.ts` ≡ BE `utils/themeIds.ts`, parity-locked by `themeIds-parity.test.ts`), applied by `normalizeThemeId` at every READ of a stored id (localStorage mirrors are not migratable) and by migrations 162 and 220 on the three stored sites (both call `remapRetiredThemeIds` in `migrations/themeOverhaul.ts`). A map entry always points at a live theme, never at another retired id. Re-pointing an entry after its migration has run does not move the rows already rewritten: `silverball` went from the default to Graphite in v2.265.6, and migration 222 (`migrations/silverballToGraphite.ts`) found the rooms from the pre-deploy snapshots. The API refuses a retired id on a write (Zod enum); only reads fold.
- **Lead and second (v2.263.0, G29).** `--color-lead` and `--color-second` sit in plain `@theme` (not `@theme inline`, so `text-lead` compiles to `var(--color-lead)` and a theme class can change it), each pointing at one of the theme's `neon-*` accents; every `.theme-*` block restates both, or it gets the default's roles. Lead paints exactly three things: the primary button (`parts/Button`, `NeonButton` primary, `ShareButton`), the active nav item in the three layouts (and the public nav's hover), and the active tab or segment of a page's tab bar. Lead as TEXT is `ink-lead` and danger text is `ink-danger` (the colour pulled a fifth toward the theme's ink, `index.css`), on a fill of at most 10%; a line, fill or dot uses the token. Danger and errors are coral (`neon-coral`), never magenta, because magenta is the lead on three themes. The shared parts' default tone stays cyan. Everything else keeps its named accent: first place is gold (`neon-amber`) everywhere, and the "you" row, links, icons, focus rings, filter chips and the protected surfaces stay on `neon-cyan`. `.aw-island` pins lead to the kit's cyan and second to its pink on the three Witness pages; an `ArcaidPage` (`.aw-screen--arcaid.aw-island`) swaps them, so Account Settings leads with the kit's pink like a room on the default theme (v2.265.6, owner 2026-11-24). A new "you are here" state uses `lead`.
- **Every theme label/description must describe the rendered palette** (background tone, ink, accents — not a metaphor), ≤ 60 chars, checked against its `.theme-<id>` block.
- **One resolution order (v2.132.0)**, documented in a block at the top of `ThemeProvider.tsx`: room public pages take this-room override (`scoreboard_prefs.roomThemes[roomId]`) → personal theme (`user_preferences.ui_theme`, NULL = use each room's default) → room default (`game_room_settings.UI_THEME`) → `dark`; admin pages take personal theme → `dark`; global pages are polarity-only. One personal theme: `components/ThemePicker.tsx` in Account and Global Settings, tiles in Display settings.
- **The this-room override is keyed by ROOM, not by device.** It rides in the `scoreboard_prefs` JSON as a third top-level key beside `desktop`/`mobile` (`PreferencesService.getRoomThemes`/`setRoomTheme`, `GET`/`PUT /api/me/room-themes`). `getRoomThemes(userId, roomId)` performs the one-shot idempotent lift of the legacy `scoreboard_prefs[device].UI_THEME` key onto the room being viewed.
- **`ThemeProvider` reads localStorage first to avoid flash** (`arcaid-theme-personal`, `arcaid-theme-room-<slug>`, `arcaid-theme-public-<slug>`). The last two are deliberately separate keys: `setPublicTheme` writes the room DEFAULT into the `public` one from the admin Settings page.
- **Appearance is the LAST step of resolution on every route class.** The viewer's preference (`dark`/`light`/`auto`, v2.130.0 — `localStorage['arcaid-appearance']` + `user_preferences.appearance`): `resolveAppearance(base, appearance)` keeps a theme whose `THEME_POLARITY` (the map beside `ALL_THEME_CLASSES`, derived from `color-scheme` in `index.css`; only `light`, `paper` + `speegle` are light) already matches and otherwise swaps in the canonical `light`/`dark` theme — so classify any new theme there or it silently never matches.
- **A card whose artwork FILLS it is a dark-token island** (v2.131.1): its root carries `sb-theme-scope sb-on-art` so the text over the fixed black scrim is theme-independent (`sb-on-art` re-anchors the inherited `color` and shadows every `sb-art-text` element). Any NEW card style that paints artwork under a scrim must do the same, or its text goes near-black-on-black under a light theme.
- **Contrast bar (v2.131.2; accents since v2.263.0).** In EVERY theme `--color-muted` must clear 4.5:1 against `--color-deep`/`--color-surface`/`--color-raised`, and `--color-faint` must clear 4.5:1 against `--color-deep`/`--color-surface` (faint carries real content — "Never", timestamps, captions — not decoration). Every accent used as text (the seven `neon-*` tokens, `lead` and `second`, `var()` resolved inside the theme) must clear 4.5:1 against `--color-deep`/`--color-surface`. `node admin-ui/scripts/contrastAudit.cjs` exits 1 on a miss (`--all` prints every accent row) and `src/__tests__/themeContrast.test.ts` runs the same `auditCss`; re-run it after adding a theme or retuning a token.
- **Carpet floor (v2.264.0, G29; owner 2026-11-23).** `components/ThemeFloor.tsx` draws the Arcaid-look carpet faintly behind themed pages in the theme's colours, as the first child of `PublicLayout`, `RoomAdminLayout` and `SuperAdminLayout` only (never the kiosk, the landing page, the Witness pages, an `ArcaidPage` (its own carpet) or an `sb-theme-scope` island; the Global Scoreboard wears the Arcaid carpet and a wash, `.gs-carpet`: G35a). It paints under positioned content (`relative`: the public scroll area, ticker, admin `main`); a new in-flow sibling there needs `relative`. Its markup, `components/themeFloorTiles.generated.ts`, comes from `scripts/arcadeCarpet.mjs` with the public tiles (same seeds; colour classes read `--color-*`, "Carpet floor" in `index.css`): never hand-edit it; regenerate, and `public/carpet/` must not change. Strength is per theme: the strongest of 16 down to 3 % (at most 16 dark, 12 light) at which primary, muted, faint, cyan, lead and second text keep 4.5:1 on deep; `contrastAudit.cjs` (`floorAudit`) and `themeContrast.test.ts` recompute it and fail a stronger `.carpet-floor` rule: re-run them after retuning a palette. High contrast never shows it.
- **The floor switch.** Room: `UI_FLOOR` (`'on'`/`'off'`, absent = on, shipped as the portal's `ui_floor`) under the room default picker in Room Settings. Viewer: `user_preferences.ui_floor` (migration 221, NULL = no choice) through `MyFloorToggle` (`components/FloorToggle.tsx`) in Account and Global Settings and a switch in Display settings; each page keeps its own control's look. `ThemeProvider` resolves it (`resolveFloor`): on a room's public pages the viewer's choice, else the room's, else on; everywhere else the viewer's, else on. First paint reads `arcaid-floor` and `arcaid-floor-public-<slug>`; the viewer's value hydrates by appearance's rule (a NULL server column never wipes a local choice, which is saved up instead).
- **The Arcaid Witness look is NOT a site theme id (W105, v2.251.0).** `/witness/install`, `/pair`, `/pair/:code` (`components/AwPageShell.tsx`) and the whole Account Settings page (G20, v2.256.0: `aw-web--wide` 1600 px; five colour groups in `SETTINGS_GROUPS`, drawn by the shared parts (see "Style guide" below), a new panel goes inside its group; background is the arcade carpet via `aw-screen--arcaid` (v2.259.0: four seamless tiles in `public/carpet/*-vN.svg` generated from the kit's colours by `scripts/arcadeCarpet.mjs`, at 16% so chrome text keeps 4.5:1; never hand-edit a tile, regenerate under a new -vN), never the Witness picture) wear the designer's kit in `public/aw-theme/`: `aw-theme.css` + `aw-theme-ext.css` are VERBATIM copies (never edit; the one source of every Witness colour, font and size, shared with the cabinet repo), `aw-web.css` is the site layer (`--aw-scale` 0.32, the 1080 background, `.aw-island` mapping the site tokens onto the kit inside `sb-theme-scope`). `lib/awTheme.ts` `useAwTheme` loads them only while such a surface is mounted; bump `AW_THEME_VERSION` when a file there changes. Components use `--aw-*` tokens and `.aw-*` classes, never a hex. Kit classes are unlayered, so they beat Tailwind utilities (a link with `.aw-body` loses its cyan).

## Style guide (G21, v2.261.0)
The look is the shipped Account Settings (G20). It lives in three places that must agree: the parts in `components/parts/`, the live page `/admin/style-guide` (`pages/StyleGuide.tsx`, super admin), and this section. Owner decisions: `docs/style-guide-plan.md` "Decisions", ADR 0042.
- **Who the pages are for.** Players on a phone at a cabinet, often one-handed and in low light; room admins and mods, also mostly on phones; unattended kiosk TVs. A desktop gets the width, never a phone column in the middle of the screen.
- **Two looks, chosen by the kind of page, never per component.**
  - *Arcaid look* (fixed dark kit on the arcade carpet): personal and global pages only (the landing page, Account Settings, My Tables, My Stats, Friends, Create Room). The root is `parts/ArcaidPage` (kit, island tokens, skin), never built by hand; the Witness picture is for the three Witness pages (`AwPageShell`) only. The Global Scoreboard (G36) is always dark on the carpet too: root `sb-theme-scope`, not `ArcaidPage` (its island turns first place red); rules `.gs-*` in `index.css`.
  - *Room's theme* (11 themes): room pages and admin pages, inside their layouts. The page root is `parts/PageShell`. They get the width and the parts, not the dark skin.
- **The parts.** `ArcaidPage` / `PageShell` (page root; `jump` adds the jump list beside the groups; `header` replaces ArcaidPage's title row, the landing page), `PageTitle`, `PanelGroup` (related panels in ONE tone: `cyan`, `pink`, `violet`, `ice`; `red` only for what can do harm), `Panel` (one card under a label; `wide` spans the row), `JumpList`, `Button` (`primary` / `secondary` / `danger`; `md` / `sm` / `xs`). `ButtonLink` is a `Button` that goes to a page; `ListRow`'s `below` holds controls under the caption. G23 (v2.268.0, owner picks, style plan decision 8) added `Field` (`TextInput` incl. `size="score"`, `TextArea`, native `Select`, `SearchInput`), `Skeleton` (`SkeletonRows`/`SkeletonTiles`, `role=status`), `EmptyState`, `Tabs` (`RailTabs` + `tabPanelProps`), `StatTiles` and `ListRow` (`ListRows`/`ListRow`): these draw with site tokens only (like `Button`, one `part-*` class set serves both looks; `.aw-island` re-points the tokens), so they take no skin switch. A part reads its skin from `PartSkinContext` (`parts/skin.tsx`): under `ArcaidPage` it emits the kit's `aw-*` classes (`public/aw-theme/aw-web.css`), elsewhere the `part-*` classes ("Shared parts on themed pages" in `index.css`), which copy the kit's geometry and take every colour from `--color-*`. Change a shape in BOTH or the two looks drift; the live page shows them side by side. In the themed CSS a tone used as TEXT is `--part-ink` (violet is pulled toward the theme's ink to clear 4.5:1), a tone used as a line, bar or dot is `--part-tone`, and glow is `light-dark(transparent, …)` so it follows the theme's `color-scheme`. A new tone or theme is checked on the live page in every theme (label and button text at 4.5:1); the theme tiles there show each theme's lead and second.

## PWA, service worker and assets
- **PWA:** `manifest.json` + `sw.js` in `admin-ui/public/`; service worker is cache-first for static assets, network-first for navigation.
- **Service-worker cache-bust is automatic (v2.28.0+), no manual bump ever.** `admin-ui/public/sw.js`'s static cache name (`arcaid-static-${BUILD_ID}`) is derived at build time by the `arcaid-sw-build-id` Vite plugin (`admin-ui/vite.config.ts` + `admin-ui/scripts/swBuildId.ts`) — a sha-256 over the emitted asset filenames + `index.html`, truncated to 12 hex chars, injected in place of the `__ARCAID_BUILD_ID__` placeholder during `closeBundle`. Same source → same BUILD_ID (deterministic); the build throws loudly if the placeholder or `dist/sw.js`/`dist/index.html` are missing.
  - Activate deletes every cache except the current `STATIC_CACHE` and the stable `IMAGE_CACHE` name, so old `arcaid-static-*` generations (and legacy `arcaid-v###` caches from pre-v2.28 installs) are swept on the next install.
  - Image mounts (`/api/catalogue-images`, `/api/styles/images`, `/api/room-assets`, `/api/score-photos`) are routed separately into `IMAGE_CACHE` — stale-while-revalidate, LRU-capped at 200 entries.
  - `sw.js` and `index.html` are served with `Cache-Control: no-cache` (`src/api/server.ts`'s `frontendStaticOptions` + the SPA catch-all) so an installed PWA always revalidates and picks up the new BUILD_ID; `/assets/*` (Vite's content-hashed bundle output) is `public, max-age=31536000, immutable`.
  - `vite dev` serves `public/sw.js` raw with the placeholder intact — harmless, dev never goes through the build plugin.
- **Never swap an `admin-ui/public/` asset in place — new filename every time.** Same-name overwrites go stale for days: `manifest.json` is no-cache and other public statics are `max-age=86400`, and the PWA/OS icon cache compounds it (a user saw the old app icon even after delete+reinstall). Renaming (`-v2` style, plus a `manifest.json?v=N` link when icons change) is the actual fix. Hashed `/assets/*` bundle output is immune (immutable by content hash). (v2.45.1)

## Toasts
- **An error toast stays until tapped (v2.233.0)**; success/info clear after 4 s (or the caller's `durationMs`, below); at most three on screen; errors carry `role="alert"` and a Dismiss button. A long refusal on a phone vanished before it could be read (owner 2026-11-08). Do not reintroduce an auto-timeout for errors.
- **The Arcaid toast on Sonner (v2.260.0, G23; style plan decisions 3 and 6).** `useToast().toast(message, type)` is the one way in; it renders `toast.custom` with Arcaid's own look (`index.css` "The Arcaid toast"). Never show Sonner's default look or pass its `richColors`/`closeButton` styling: the owner rejected library-default toasts as AI-generic. The 4 s clock is the rail's CSS animation (`animationend` dismisses), paused by hover, focus and the `tab-hidden` class; keep its duration under reduced motion. Phones (≤600 px, Sonner's own breakpoint) get `top-center` below the safe area, desktop `bottom-right` (v2.260.1, owner): toasts sit above dialogs, and at the bottom a stack covered their buttons. Sonner adds a toast one tick after the call, so a test waits (`findBy…`); in jsdom React hears `webkitAnimationEnd`, not `animationend`.
- **A toast may name its heading, its clock and a link (v2.265.2, v2.265.3):** `toast(message, type, { label, durationMs, href, hrefHint })`. `label` replaces Done / Heads up / Didn't work for a toast that reports a standing fact, not the result of an action (drawn like the default headings, no new colour: the type still picks the tone); `durationMs` sets the rail's `--arc-toast-ms` for a message of several lines and does nothing on an error. A line break in the message is a new line (`white-space: pre-line`). A toast that fires by itself on arriving at a page says its piece ONCE and remembers that in localStorage, keyed on its content: never on every navigation, never on every reload (v2.265.5; the owner got the room toast on each refresh of the installed app), and never once per room when it says the same thing in each (v2.265.8). `href` makes the whole toast ONE in-app link (`.arc-toast__go`, an `<a>` whose `::after` covers the card; never a `<button>`, because Sonner starts no swipe on a button and the toast must still swipe away); a press that travelled more than 8 px is a swipe and is dropped; the × only closes; an error is never a link.
- **The room's "Arcaid Witness" toast (v2.265.2, owner 2026-11-23: the standing lines were clutter).** On a room page the paired devices that send here are ONE toast, not lines in the notices row: `roomToastLines` (`lib/witnessScoresGoTo.ts`) puts devices with the same answer in one sentence, `firstRoomToast` says each device's answer once in this browser, in whichever room it is met first (`arcaid_room_toast_said`, one list of the newest 60, no expiry and no forgetting; memory only when storage is blocked); the answers are `roomToastKeys` (one `deviceNoticeKey` per device that sends here: never the room, since a device set to all rooms answers the same in each, and never the not-watching tail, which flips every time a cabinet is played), so a newly paired device or a new target is news and a room, a refresh or an answer said before is not (v2.265.8; once per room was still "often" for the owner), and `WitnessScoresGoTo` fires it from the routing read itself (never from state, which still holds the last room's lines while a new room loads). ## Styling gotchas
- **Touch-screen inputs are 16px (v2.203.2).** iOS Safari zooms the page in on focus of any text field under 16px and stays zoomed; an unlayered `@media (pointer: coarse) { input, select, textarea { font-size: 16px } }` in `admin-ui/src/index.css` outranks every `text-sm`/`text-xs` utility. Never fix it with `maximum-scale=1` (Android then blocks pinch-zoom), and never give a touch input an `!important` size under 16px.
- **`GlobalScoreboardA5.test` reads the FIRST `@media (prefers-reduced-motion: reduce)` block in `index.css`** and expects the hero sweep rule in it. Gate a new animation with `prefers-reduced-motion: no-preference` instead of adding a `reduce` block above it (v2.236.0).
- **Tests wait 5 s by default (X14):** `setupTests.ts` sets `asyncUtilTimeout: 5000` for every `findBy*` / `waitFor` (`testTimeout` 15 s above it), so never add a per-call `{ timeout }` to cure a CI flake. A value that arrives after the first render is awaited by its TEXT (`waitFor(() => expect(el).toHaveTextContent(...))`), never by `findByTestId` of an element that is already there.
- **Tailwind on Windows:** must use `@tailwindcss/postcss` (NOT `@tailwindcss/vite` — oxide scanner fails silently).
